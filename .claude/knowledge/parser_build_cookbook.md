- **fetch**: NO ratesheet in the email — mail from `pricingdesk@thelender.com` (no subject) carries only a "Rates" link. Selenium scrapes `wholesale.thelender.com/ratesheets/`; each program is an `h2` + `ul` whose `li[1]` is the current sheet, so the date in the filename never needs parsing. NonQM `.xlsx` (all 3 programs) + theNONI `.pdf` (zone `DSCR`, cross-check only — verified identical to the Excel).
- **tables**: 24 (field_1–24) — NONI 8 (field_1–8), FN NONI 7 (field_9–15), NQHEM 9 (field_16–24). 15 are FICO×CLTV / band grids, 3 are single-per-program max-price caps, 2 dated promos, 6 lock/prepay

- **adj_sections**: 17 cell-range slices (`workBook.getSheet(SHEET, colStart, colEnd, rowStart, rowEnd)`) — each program packs ladder + grids + caps + promo + prose + the lender's own interactive Pricer panel onto ONE sheet, so whole-sheet parsing would ingest the Pricer panel's formula output
- **modes**: `INTEREST_ONLY_MODE` (existing) + `SUPER_NONI_MODE = "Super NONI"` (local String constant in the Tables class — nothing added to packs/quote). hitAll. theSuperNONI is a mode, not a product: own DSCR-band row, own CO-Refi row, own eligibility grid, but shares theNONI's ladder (emitted a 3rd time under the mode — a mode with no rate rows resolves and then finds nothing to price)
- **validations**: 87 (NONI 34 / FN 22 / NQHEM 31) incl. 6 FICO×loan×purpose grids + 2 footnote overlays (theSuperNONI −5% LTV on 8 cells; NQHEM non-PRA 85% cap on 4 cells) modelled as separate gated grids so printed LTVs stay intact
- **qc_issues**:
  - `colRange` needs **N+1 boundaries for N columns** — 9 boundaries on a 9-column grid silently parsed 8 columns AND caused 18 detector remainders (the unconsumed column left label+value fragments). Column counts differ per program: NONI 8, FN 6, NQHEM 9.
  - `premiumCaps()` **sums** its list, never MINs → 4 theNONI caps under one gate would blend to ≈ −5.0. Fix: ONE cap table per program, `HitStrategy.HitHighest` + `100 − price` value handler. See [[pricing_premium_caps_sum_not_min]].
  - `SUPER_NONI_MODE` resolver clause was initially not product-gated (a qualifying FN quote picked up the mode string; inert but a trap for future rows). Fixed with `nonQMProduct(TheNONI).and(...)` — 4 existing lenders (LoanStream/NewRez/NMSI/JetAdvantage) already gate modes this way, so `non_qm_product` IS available at mode-resolution time.
  - `-Daccept.new.adj` must be re-run after a wave adds `detector.register()` calls, or the expected file keeps the old section list (functionally inert — `verify()` defaults missing sections to "" — but misleading).
- **special**:
  - The yaml/spec cell ranges are **value-only**; crawl labels sit 1–3 columns to the LEFT, so every adjustment slice must be widened leftward or PageParser matches zero rows. Skip-block coords were also off by one column (FN Pricer panel is L–N, not K–M).
  - `followedByNumber(true)` needed on every table whose row labels start with a digit (`1.00-1.24`, `150,001 - 250,000`, `780+`).
  - Two PPP tables per DSCR program (5% Fixed vs "other allowable") are indistinguishable in the quote model — `PrepaymentPenaltyType` carries only the term, not the structure. Split on `state("MS")` / `.not()` grounded in the sheet's own NOTE 4 ("only declining structures allowed in MS"). A real fix needs a `prepaymentPenaltyStructure` field.
  - NQHEM's PREPAY block carries an LLPA column AND a Max Price column side by side → read the same slice twice with different column windows; the cap rows use `crawlPattern("60 Months \\S+")` to swallow the LLPA token into the label.
  - NQHEM August Special is printed twice (once per doc column) → slice only the left copy. theNONI's promo must never reach FN NONI (sheet excludes Foreign Nationals) — enforced by the `nonQMProduct(TheNONI)` gate + no FN slice reading the NONI sheet.
  - NQHEM Alt Doc rate ladder is byte-identical to Full Doc (25/25 rows) → one ladder read; re-verify on sheet updates or Alt Doc prices go stale silently.
  - No-score borrowers: `NO_CREDIT.or(FOREIGN_CREDIT)` = `fico(0,0).or(fico(1,1))` — existing sentinels (precedent LoganFinanceNonQM).
  - `state(...)` only accepts codes in `base/core/.../States.java` — `PR`/`GU` throw at class-init; only `VI` exists.
  - ARM terms (margin/caps/index/reset) are **not modelled anywhere** in the parser layer — `Product` has no field for them, so "don't share the ARM constant" is vacuous advice today.
  - 4 rows parsed but gated `ALL.not()` (unpriceable, no quote field): ACH Waiver, Short Term Rental ×2, CPA P&L Plus w/ 3mo bank stmts (the last one shares `alt_doc_cpa_p_l_only_*` with plain CPA P&L and `ConditionTableInfo` sums matching rows → wiring both double-stacks; needs a new `NonQMDocumentType`).
  - Lender's own `Final Price` formula is a **priority chain**, not a MIN — diverges from the parser at loan > $2.5M with no prepay penalty (chain 100.500 vs MIN 100.000). Parser implements MIN.
- **similar_to**: ["PlazaHomeNonQM", "LoganFinanceNonQM"]
- **build_date**: 2026-08-24 (MOSO-17041 epic; 17042/17043/17044)
- **build_stats**: 3 dev waves (one per program) + 1 QC pass + 1 grid-verification pass; 0 test retries — every wave's tests passed on first clean run

## PageParser region anchored on a shorter neighboring column silently truncates (BluePoint BlueXpanded, 2026-09-12)

When a page prints two side-by-side column-boxes of clearly DIFFERENT heights and a `PdfUtils.extractTextBetween`
region uses a heading from the SHORTER column as its bottom-Y anchor for extracting the TALLER column's content,
the extraction silently truncates right where the shorter column's heading sits — even though the x-range filter
looks correct on paper. Symptom: `PageParser` throws `Can not parse row with label: 'X'` for a row that is
genuinely printed on the page, just further down than the (wrong) bottom anchor's Y-position. This is NOT a
crawl-pattern or column-count bug — the fix is choosing a bottom anchor that's guaranteed to sit below the FULL
height of the column actually being extracted (e.g. a footer banner that prints below both columns), not fixing
anything about the row-matching regex itself. First hit: BluePoint Full/Alt-Doc BlueXpanded and Flex Full/Alt-Doc
BlueXpanded (pages 10-11) — both used `LOCK_TERMS` (a heading in the shorter "Max Price then Lock Terms" column)
as the bottom anchor for the taller "ARM Terms then 6-row Prepay Penalty table" column; fixed by anchoring on
`MIN_PRICE_BLOCK` ("LPC AVAILABLE TO MAX PRICE CAPS") instead, which prints below both columns on both pages.
